# Changelog

All notable changes to this extension are documented here. The format follows
[Keep a Changelog](https://keepachangelog.com/en/1.1.0/); versions follow
[Semantic Versioning](https://semver.org/).

## [1.0.2] - 2026-11-23

### Added
- **Language versions kept in step (Plus).** On a page with language versions, a move is carried into the other languages, and what else is done to an element is offered to its counterparts there, in a dialog per action (`ElementSync`, endpoints `…/element/{id}/versions` and `…/versions/{create,image,move,visibility,delete}`):
  - a new element (inserted, once its form is saved and closed, or duplicated): per language **Insert at the same place and translate** (a copy after the counterpart of the element before it, translated by the translation service of the settings, linked as current, with the elements in it), **Link with an existing element** (an element there that belongs to none yet, those of the same type first) or **Do not insert, only in this language**; **Only here** for none. On the page of a version the main language comes first; the other versions follow through its element. Asked only with translations at hand (the switch *Request translations* and a translation service set up); a copy whose translation the service refuses or cannot answer is removed again;
  - a replaced image (context menu, the element's menu, the image tools while editing): the same file in the counterparts that are ticked; alternative text and caption stay those of each language;
  - move (arrow keys, menu, dragging): the counterparts go to the matching place without asking, so the elements stand in the same order in every language;
  - hide and show: the counterparts get the same visibility;
  - delete: the counterparts that are ticked are deleted as well; the others stay and lose their link (state *not linked*). This dialog replaces the browser's question where the element has counterparts.

  A message says per language what was done or why not. Nothing of this without Plus for the website, linked language versions and the switch *Edit language versions*: the editor does not ask, the endpoints answer 403, every action applies to its own page as before. Every write goes through Contao's operations, voters and versions (`StructureEditor`, `FieldWriter`) and needs Plus for the page of the language and, except for the image, the switch *Create, move and delete elements*. Versions made before the editor are paired first, so the question also comes for elements still shown as *not linked*; a new element is left out of that pairing (`ElementPairing::pair()` and `pairContainer()` take a list of elements to leave out). New texts `editor.sync_*` in the eleven languages.

### Changed
- The main action of a dialog or window (**Replace there too**, **Apply**, **Delete**, **Translate all fields**, **Save** …) stands out in Contao's orange where the back end draws every button alike (Contao without a skin): a shade darker than Contao's `--contao`, so that its white text stays readable in both colour schemes (5 : 1), with white icons; disabled it stays grey. A skin that colours the back end's main action keeps giving it its colours. New variables `--nfe-primary`, `--nfe-primary-hover`, `--nfe-primary-text`.
- The main action stands at the right end of its row of buttons, the less important ones before it: in every dialog (**Cancel**, **Replace there too**), in the window Translate (**Cancel**, **Save**), on the cards of the view Languages (**Link with an element**, **Take over**), in the bar of a page (**Publish**) and of the view Languages; a dialog without fields opens with the focus on it. Where a row is too narrow, its "…" goes before the main action, which stays.

### Fixed
- **New page** in the bar of a page: the sidebar is titled **New page** again instead of "[object PointerEvent]".
- Before Contao 5.7, the addresses of the editor's script, stylesheet, icons and accessibility check carry a version (a short hash of the file), so that after an update the browser loads the new files instead of keeping those of the old version. Contao 5.7 versions them itself; its version stays.

## [1.0.1] - 2026-11-18

### Fixed
- Every action that runs in the background shows that it runs: the button keeps its spinner also when the window or the sidebar is drawn again meanwhile (translation window, languages, Save after Ctrl+S); work started from a menu entry shows it at the menu's button or, without one, in a note at the bottom edge; the page in the preview is dimmed with **Updating the page …** while it loads again after a change; views, windows and Contao's forms in the sidebar show **Loading …** with a spinner until their content is there.
- Translation window: while it works, a veil with a spinner lies over its fields and says what runs (**Translating …**, **Loading …**, **Saving …**); for one field only over that field. Nothing in the window can be typed or chosen meanwhile; it closes without asking.
- **Translate whole page** and **Apply all proposals**: a veil over the comparison says how far they are (element n of m), the card being worked on is marked, nothing can be used until they are done. The writing aid lies under a veil (**Writing proposals …**) while the AI writes.
- After **Save** in Contao's form in the sidebar (**All fields**, properties, settings), the page in the preview loads again at once, without fetching the structure first.

## [1.0.0] - 2026-11-13

Initial release. Runs on Contao 5.3 to 6.0 with PHP 8.2 to 8.5, as far as the Contao version supports it (Contao 5.7 needs PHP 8.3, Contao 6.0 PHP 8.4).

### Added
- Editing in Contao's own front-end preview, switched on with **Edit page**; visitors get the page unchanged.
- Every text of the page edited where it is shown and saved into the field it comes from: headlines, texts, images, the other text fields of elements and front-end modules, rows of lists, cells of tables, records of child tables and records an element shows from another table through a relation of the data container (a FAQ category with its questions, an entry of a catalogue; an alias is no text), also of other extensions. Contao's form of every element in a sidebar docked next to the page.
- The tab with the type on the frame of the selected element opens its menu: every action for the element, the keys that do the same (Enter, Alt+arrow keys, Delete) and the grip that drags it; the same entries as the context menu. While a text or an image is edited, its tools stand as a second tab next to it.
- **Frontend Editor** at the top of the back end, next to **Preview** (a screen with a pen; on small screens the symbol alone): opens the preview of the page the back end shows with the editor switched on.
- The sidebar beside the page or over it: a strip at the right edge collapses and expands it, its pin keeps it beside the page (default) or lets it lie over the page, where it opens when a view needs it and closes again afterwards; its width can be dragged at a visible grip. The editor follows the back end's look: Contao's buttons and colours, or those of a back-end skin.
- Contao's breadcrumb of the selected element at the top of the sidebar, one click each: **All pages** (Contao's page tree, where new pages are created; Plus), the page, the article, the element.
- Rich text (fields with Contao's TinyMCE; not the HTML element) is formatted with the toolbar of the text; **HTML editor** there switches to Contao's own TinyMCE on the page, inline, with the configuration of Contao's form for the field (images and links through Contao's picker, tables, source code). Its toolbar stands in a bar above the tabs of the element, flush with the frame, always on top of the page, and can be dragged anywhere in the window; the choice and the place are remembered. A value of another field with HTML tags offers **HTML source** (Contao's form at this field). On a phone the tools of a text are behind one button that opens them as a dropdown; TinyMCE is not offered there.
- **Plus:** the tab of an element shows its language versions: a symbol where every version is there and current, **Translation outdated** or **not in all languages** / **not linked** where something is missing.
- **Plus:** the headline and teaser of news and events edited right on the page in lists and readers, saved into the post.
- Context menu on the page; insert, move, duplicate, hide and delete elements, also inside accordions, sliders and element groups; create articles. For web designers: templates, front-end modules, layout, form fields.
- **Plus:** pages, posts (news, events, FAQ), the extensions' modules, and language versions: a translation window per element with every text of the element (also entries, records it shows from another table and image texts; a record both language versions show is never overwritten), proposals of Azure Translator, DeepL or an AI model per field or for all fields, marked as machine translation below the text translated into; outdated translations shown; whole pages translated at once, with a note when there is nothing to translate or no element gets a proposal. An element written in a language version first is taken over into the main language (**Take over into …**), linked as current, and translated there in the same window. The translation window translates in any direction between the languages of the page (**Translate from**, **Translate into**, **Swap languages**; on a version into the main language at first) and sets the states accordingly: into the main language its other versions become outdated, between two versions the target takes the state of the source. It also opens from the form **All fields**; the quick guide explains it on pages with language versions. Elements inside other elements (accordion, element group …, with the section headline of an accordion) and the content elements of posts (news, events and posts of extensions, linked with changelanguage) are paired, compared, translated and taken over like the elements of a page; the view **Languages** shows them indented under their element and, on the page of a post, as a group of the post.
- **Plus:** records translated on their own in the same window, with the type and title of the record: page settings (title, page title, description), posts (title, teaser, meta fields), archives (news archive, calendar, FAQ category) and Contao's front-end modules. A record without a version in the other language is linked with an existing one (the one at the same place proposed) or created as a copy there: posts and archives with changelanguage's fields, other records in a table of the editor; linking two archives links their posts by their order; from a version without a record in the main language, the chosen or copied record of the main language becomes the main record, and records that already have a version are not offered. A new post is created at once in every language whose archive is linked (copies, not published, same dates and author; written in a version first, also in the main language); a copy gets its address from the translated title. Archives translated on their own leave their posts to their own translation.
- **Pro:** AI writing aid, SEO and accessibility checks (the main heading counted as search engines read the source, also one shown only at some widths), the page in the width of a phone or tablet, own CSS or SCSS per page. The modules of the website and of other extensions in the view **Modules**; their lists get the operation **Translate** (an icon before **Edit**), and their records and front-end modules are translated and linked like Contao's own.
- A click on a link or button of the page never leaves it: it selects or edits; Ctrl+click (Cmd+click) or **Open link** follows the link. A **Quick guide** in the head of the sidebar explains selecting, editing, links, the context menu and the keyboard; the first start points to it.
- A row of buttons always stays one line: what does not fit is behind **…** at its end (**Save** stays in the row), on phones, in a narrow sidebar and in the tabs of an element.
- Feedback on every click: a spinner on the button whose request runs; the sidebar keeps its place when it is drawn again; the page shows a saved form at once.
- Contao's permissions apply to every record and field; the extension's switches only narrow them. Every change is saved as a Contao version.
- Back end and editor in eleven languages; documentation in English and German; unit tests.

After installing: update the database, then allow the editor for the user groups of the editors (**User groups**).
